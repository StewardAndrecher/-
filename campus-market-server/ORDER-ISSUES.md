# 第104课：交易问题反馈与本人记录

订单详情新增“交易问题反馈与本人记录”。参与者可对PAID、DELIVERED、COMPLETED订单提交商品状况、交接履约或其他问题；未付款、已取消、超时关闭不能提交。每单每方一次，页面仅展示本人首次记录，对方无法读取说明。

GET /api/orders/{id}/issue 返回orderId/userId/orderStatus/viewerRole/canSubmit/issue，issue为空或reason/description/createdAt。POST同路径请求reason和description，首次201，相同规范化内容重放200，不同内容409，不覆盖首次时间或正文。reason严格ITEM_CONDITION/HANDOVER/OTHER；说明10至1000个Unicode字符，统一换行与首尾空白，拒绝控制字符、未配对代理字符及JSON数值/布尔隐式转字符串。客户端userId/applicantId不能指定身份。

新增order_issues，主键(order_id,applicant_id)，引用订单和用户，数据库检查类型和长度。新增V104迁移；旧31份SQL冻结不变，新库32份迁移，24张表含Flyway历史。已有101库只执行104创建空表，不回填。

读取使用只读REPEATABLE_READ快照；写入READ_COMMITTED，锁订单后再次验证会话。只锁订单，不再锁商品，避免改变原锁顺序。数据库主键与服务比较共同保障幂等。匿名401，非参与者与未知订单统一404，参数400，状态/内容冲突409，异常历史记录503，数据库故障500。响应no-store。

只新增本人反馈记录，不改订单、商品、评价、交易事件、MQ任务或通知，不执行退款。本课仅完成用户侧反馈提交及本人记录，管理员工单列表、处理与结果通知尚未接入，不能宣称售后闭环完成。

前端先确认再提交，用权威回执更新页面。取消不发请求；确认期间切账号或隐藏页面不提交；迟到响应失效。超时或回执异常清空资格，提示先重新加载，不自动重试。正文按Vue文本显示，避免HTML注入。页面输入中的私人内容仅展示给本人，不发送给对方或消息队列。

测试使用独立临时MySQL。真实业务库部署仅验证101到104的一份迁移及空表，并核对原记录、表定义、计数、图片与配置。用户侧页面写入均用临时新账号和订单。小程序及App验收为编译，手机运行单独计。


## 第105课：反馈处理与结果通知

管理员可逐条答复或不予支持；本人记录显示处理结果，可靠站内通知仅提醒该提交人。不改变交易或执行退款。新增V105空结果表，旧32份迁移不变，新库33份迁移。完整说明见 ORDER-ISSUE-RESOLUTIONS.md。


第106课新增GET /api/orders/issues与我的订单下的本人反馈清单，可按当前角色与处理状态查找已提交反馈。清单不含反馈/处理正文，进入原详情再读取本人说明；详见ORDER-ISSUE-LIST.md。
