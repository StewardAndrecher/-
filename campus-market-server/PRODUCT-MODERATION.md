# 第90课：商品巡查、违规下架与卖家复核

本课采用发布后巡查，不把原发布方式改成发布前待审核。管理员查看商品并下架违规内容，卖家看到原因、可编辑整改后申请复核，管理员解除限制后仍由卖家手动上架。没有新增Maven/npm依赖。

## 状态与原交易规则

独立审核状态CLEAR→BLOCKED→APPEALED→CLEAR；管理员也可从BLOCKED直接解除。无审核记录视为CLEAR。商品业务状态仍ON_SALE/OFF_SHELF/SOLD，不修改旧DTO或历史商品。

BLOCK将商品设为OFF_SHELF并添加平台限制；限制期间卖家不能上架或标记售出，可以修改内容。APPEAL保留平台原原因，保存整改申请，仍下架。RELEASE清除限制，仍下架，不替卖家发布。三个操作都会令商品version+1，确保审核与卖家编辑冲突时必须刷新。已SOLD或有有效订单占用时拒绝处理，不自动取消订单、不模拟付款或退款。

所有写入先锁商品，保持原有商品→订单加锁顺序；READ_COMMITTED下核对最新状态和版本。新请求须version、规范UUID requestId、2～200字符reason。同一操作者和requestId唯一；相同原载荷重试返回当前权威结果/replayed=true，不再执行旧决定或重复审计；载荷、商品或版本不同却复用key返回409。其他管理员不能通过重放读取无权结果；管理员撤权和卖家归属均先检查。

## API

- GET /api/admin/products?page=1&size=10&keyword=&status=&moderationState=：全状态巡查，最多20件；支持字面关键词及CLEAR/BLOCKED/APPEALED筛选，按ID倒序稳定分页。
- GET /api/admin/products/{id}/moderation：商品当前内容、审核状态与最近20条处理事件。
- POST /api/admin/products/{id}/moderation/actions：action为BLOCK或RELEASE。
- GET /api/products/{id}/moderation：只有该商品卖家可读。
- POST /api/products/{id}/moderation/appeals：只有卖家可提交复核。

管理路由沿用实时ADMIN拦截，服务写入口再次校验；卖家路由使用当前会话并核对商品归属，其他账号404。成功读写均no-store。公开商品响应不增加处理原因或审核记录；管理员角色不绕过原公共商品详情的卖家归属规则，应使用管理详情接口。

## 数据库和缓存

V90新增product_moderation_events与product_moderation两表。事件保存目标商品、真实操作者、角色、原/目标状态、版本、原因、请求标识、处理时商品内容快照和时间。当前审核表引用最后事件；事件证据不随后续编辑被覆盖。角色和请求参数中的actorId不能伪造审计人。

商品状态/版本、事件、当前审核状态同事务提交；任意写入失败全部回滚，Redis仅在提交后清除旧版本。原公开详情先查数据库当前状态/版本，旧缓存不能恢复已下架商品。事件完整留库，页面仅展示最近20条，不把它称为完整历史分页。

原27份迁移、V74参考、原16张业务表结构/行/计数及管理员授权不改；只新增V90。新库28份迁移，18张业务表。本机从74 BASELINE+87+89新增90，历史4条。V90两条DDL不承诺整份事务回滚，失败应核对现场，不能自动repair/clean。

## 前端与重试

管理中心新增商品审核入口和巡查列表，打开单个商品查看内容、平台处理原因、整改申请及近期证据；填写原因并确认下架或解除。我的发布新增“平台处理与复核”，卖家可以查看原因、前往编辑整改、提交复核。权限切换、隐藏和卸载不接受旧请求返回。

写入使用唯一请求标识；结果未知时保留同一原载荷供手动重试，不自动重发、不允许随意改原因后复用标识。已知400/401/403/404/409拒绝后清掉旧详情，需刷新；成功或重放后展示服务器当前结果。
