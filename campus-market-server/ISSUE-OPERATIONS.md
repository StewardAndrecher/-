# 第107课：反馈处理概览与等待时长筛选

管理中心新增“反馈处理概览”。GET /api/admin/order-issues/overview返回sampledAt、total、open、resolved、answered、dismissed、openOver24h、openOver72h、oldestOpenAt。仅实时有效管理员可读；匿名401、普通用户403、异常记录503、数据库错误500，no-store。

total=open+resolved；resolved=answered+dismissed。待处理满72小时是满24小时子集，满24小时又是open子集，不能相加。计数单位是反馈，订单双方各自提交时分别计数。只统计尚无对应处理记录的反馈，不把已处理的历史老反馈算作积压。关联始终使用(order_id,applicant_id)复合键。

单条聚合SQL使用数据库CURRENT_TIMESTAMP(6)为统一采样时间，空表也返回一行0计数和null最早时间。概览不含反馈/处理正文、订单编号、提交人/管理员编号或请求键；不写任何业务表、通知任务或权限。非法参与关系、付款/反馈/处理时间倒置、未来时间等返回503，不伪造“健康的0积压”。

原GET /api/admin/order-issues新增age=ALL/OVER_24H/OVER_72H，缺省ALL。只有status=OPEN允许后两种；显式空、未知、大小写/空白不匹配或状态组合无效返回400。旧调用缺省age仍按最新提交排序。

时长筛选以服务器采样时间减24/72小时作为固定阈值，包含恰好达到边界的反馈。COUNT与SELECT使用同一只读REPEATABLE_READ快照和同一阈值；SQL先筛选后分页，最多20条，越界收缩到最后一页。等待时长筛选按created_at、order_id、applicant_id正序，使最早提交的工单优先；ALL时长保持原倒序。

列表响应增加age和sampledAt回显。原有status/page/size/total/totalPages/items及记录字段保持含义；前后端需一起更新。跨HTTP请求不是冻结快照，概览进入列表会重新采样，统计可能因新反馈或管理员处理变化。24/72小时仅用于运营优先级，不是自动关闭、退款或处理承诺期限。

前端严格检查聚合分区、嵌套子集、最早时间与时长一致；等待时长列表核对筛选回显、阈值、排序和复合编号。时间比较保留微秒/纳秒文本精度，按服务器本地时间字段作日历运算，不读取手机时钟决定工单是否超时。复用现有管理加载器，账号/令牌变化、隐藏/卸载、旧请求均不能重现旧管理数据。

入口管理中心→反馈处理概览→满72/24小时待处理→单条工单。列表也提供时长选项，切换状态自动回到age=ALL，切换条件回到第一页；非法深链接不发请求。保存原处理功能、幂等和通知链路，不自动执行处理。

无新Maven/NPM依赖、表、索引、迁移或MQ资源。旧33份迁移冻结，新库仍25张表（含历史）。没有进行大规模压测；需要后续依据查询计划和实际数据规模优化排序/分页。

测试覆盖匿名/普通用户/撤权/会话失效、空表、双方独立、两种结果分区、已处理老记录排除、24/72小时边界、时钟篡改无效、过滤后分页、最早优先、最小字段、只读、异常时间及并发处理快照。测试写入仅在临时私有MySQL。
