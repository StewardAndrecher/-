# 第102课：交易评价的可靠站内通知

首次提交已完成订单的评价时，后端根据登录身份和订单参与者确定接收人，只提醒另一方。评价和 notification_outbox 的 INSERT 使用同一个数据库事务：任一写入失败就一起回滚。MQ暂时不可用不影响已经提交的评价，任务由现有通知调度器退避重试。

## 数据与消息边界

不增加依赖、数据表、SQL迁移或MQ权限。复用 ORDER 类别和现有通知队列，source_key 为 ORDER_REVIEW:订单ID:评价人ID，resource_id 为订单ID。同一订单每方只评价一次；同内容重放返回200，不同内容返回409，两者均不新增通知。此前已存在的评价不补发。

通知标题为“收到交易评价”，正文仅提示进入订单详情，不包含评分、评价文字、商品标题或双方身份。MQ载荷仍只有 schema 和 eventId，消费者从数据库读取接收人和内容。消息可能重复传输，数据库 event_id 唯一键和事务处理保证同一任务只保存一条站内通知；这不表示消息传输恰好一次。

## 前端行为

首次提交显示“评价已保存，已安排站内提醒对方。”，这表示任务已经提交，并非对方已收到或阅读。重放显示不会重复提醒。消息中心 ORDER 标签改为“订单消息”。点击通知仍先确认已读回执，再进入订单详情，评价入口继续验证登录身份和订单所有权。

## 验收方法

在独立临时MySQL和RabbitMQ中运行 OrderReviewIntegrationTest 与 OrderReviewNotificationMqIntegrationTest，验证双方接收方向、重放、冲突、隐私、事务回滚、MQ无法路由后的恢复、持久化消息、重复消费和失败停放。真实业务库只做读取对比，不写入测试评价或发送测试提醒。不需要手机设备即可完成代码测试和Web验收；手机运行另计。

执行后端全部测试：python3 scripts/test_backend.py --offline
执行前端及桌面测试：python3 tools/test_quick.py
编译各端：sh tools/build.sh all
