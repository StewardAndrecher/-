# 第116课：有效登录会话分页明细

复用login_sessions表，不新增软件包、SQL迁移、索引、账号权限或令牌持久化。

## 接口

GET /api/users/me/sessions/active?page=1&size=10，使用当前Bearer会话。

只接受page（1～1000000，默认1）和size（1～20，默认10），每个参数必须是单个规范正整数。未知参数、重复参数、空值、前导零、科学计数法均400 / INVALID_SESSION_QUERY。先鉴权，匿名、伪造、已退出或已到期会话401。客户端不能传userId切换账号。

响应：userId、items、total、page、size、totalPages、sampledAt。每条items只有current、createdAt、expiresAt。只列当前账号在sampledAt仍有效且未撤销的会话，当前登录也包含在内，所以总数至少1；无有效身份返回401，不返回假空列表。越界页收缩到最后一页。成功响应no-store / Pragma:no-cache，不创建、撤销或删除会话。

没有公开会话编号、令牌、哈希、IP、设备或其他用户资料。内部以created_at DESC, token_hash DESC解决同秒排序，哈希只在服务器排序，不出现在JSON和前端。多条创建/到期时间相同的其他会话仍是不同记录，前端不会按时间去重。

## 事务语义

REPEATABLE_READ只读事务内先验证当前会话并捕获数据库sampledAt，再使用同一所有者、采样时间及MVCC快照查询总数和本页。避免单次响应中count与items混入并发登录。所有SQL值参数绑定；只有固定SQL排序，没有客户端排序字段拼接。

每次翻页是新的事务和新的采样，不是冻结快照。新登录、退出、到期会改变偏移位置，跨页可能重复/漏项；刷新重新核对。没有声称这是设备管理或历史审计，过期/撤销记录不展示。沿用idx_sessions_user；没有做生产规模性能压测。

## uni-app入口

个人资料 → 登录会话管理 → 查看有效登录明细。默认每页10条，显示当前登录标记、创建/到期时间、服务器采样时间、上一页/下一页。仍通过原会话管理页面确认退出其他登录，本课没有逐条撤销功能。

前端严格验证账号、分页回显、数量关系、条目字段、真实日期、排序和当前标记。单页完整列表要求恰好一个current，分页时current可以在另一页。换账号/换令牌、隐藏/卸载清空旧数据，迟到响应无法覆盖新页面。401、500或无效响应不渲染假空列表，不自动重发。

## 验收

新增27项真实隔离数据库接口测试、1项文档契约测试、30项前端测试。覆盖鉴权优先、账号隔离、重复和注入参数、失效边界、越界收缩、同秒排序、只读数据、REPEATABLE_READ快照与并发新增、敏感字段缺失以及页面生命周期。保持原退出其他登录与改密流程兼容。全部写入样本只在私有测试库，真实账号和权限不用于操作测试。
