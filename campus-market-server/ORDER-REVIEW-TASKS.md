# 第103课：待评价与已评价订单清单

我的订单新增“待评价与评价记录”入口，保留当前买家/卖家角色。新页面只统计该角色下已完成的订单，可以切换待评价和已评价，默认待评价。是否已评价只看当前用户自己的记录，对方提交不改变自己的待评价资格。点击“去评价/查看评价”进入现有评价页，返回后重新读取权威结果。

GET /api/orders/review-tasks?role=BUYER&status=PENDING&page=1&size=10
role为BUYER/SELLER，status为PENDING/REVIEWED，page为1至1000000，每页1至20条；默认BUYER/PENDING/1/10。所有响应no-store。未登录或失效会话401，非法参数400，数据库故障500，异常评价时间503，不返回伪造空列表。

身份仅来自会话；客户端userId不能改变范围。LEFT JOIN只连接当前用户的评价，通过是否存在记录判断本人待评价。角色列名来自服务端白名单，用户、分页值通过参数绑定。SQL完成筛选后分页，不能先取一页再过滤。按订单完成时间DESC、订单ID DESC排序。

summary包含当前身份全部已完成订单的total/pending/reviewed，不随状态或分页变化。Page.total是当前状态总数。空集仍为1/1页，请求页超界收缩到最后一页。汇总、总数和清单在同一只读REPEATABLE_READ事务中读取；跨HTTP请求不承诺同一个数据库快照。

每行仅orderId/productTitleSnapshot/priceInCentsSnapshot/completedAt/reviewedAt。保留订单标题与金额快照，不返回对方身份、评分和评价文字。列表查询不更新订单、不创建评价、不生成通知。不新增依赖、表、迁移、MQ资源或权限。

前端验证当前账号、角色、状态、统计和、页码收缩、条数、去重、顺序、日期和最小字段集合。账号/令牌切换、隐藏或卸载页面时丢弃在途响应；请求失败清掉旧清单，避免显示上一条件下的私有记录。只能打开当前清单中的订单，导航重复点击受到保护。

测试在独立临时MySQL中进行，页面写入只用隔离发布环境的新账号和新订单。真实业务库只读比对。新增前后端自动化测试，覆盖身份隔离、对方评价不影响本人、分页与聚合一致性、并发提交下的RR快照、提交后待评数量减少、迟到响应和失败清理。
