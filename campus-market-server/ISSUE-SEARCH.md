# 第108课：反馈工单精确检索与返回条件恢复

管理员工单列表新增订单编号输入框，按完整编号查找一笔订单的双方反馈，并与当前状态和等待时长取交集。进入详情时带入已经验证的筛选条件、实际显示页码和每页数量，返回时重新读取该条件下最新结果；若处理使末页消失，后端自动收缩页码。

GET /api/admin/order-issues?status=ALL&age=ALL&orderId=7&page=1&size=10

orderId缺省或空文本表示不限，非空必须为1至9007199254740991的规范正整数文本。不接受首尾空白、前导零、正负号、指数、小数、全角数字或超出安全整数范围；无效400。查询身份仍由实时管理员会话决定，知道编号不能获得权限。匿名401、普通账号403；不存在的订单或没有反馈均为空列表。

查询使用AND i.order_id=?及绑定参数，不拼接输入。COUNT和分页共享原只读REPEATABLE_READ快照、采样时间和条件，SQL先筛选后分页。查询响应新增orderId数字或null；同一订单最多双方两条反馈。原status/age/sampledAt/分页/记录含义不变；旧服务重载保持不筛订单的行为。

前端orderId始终使用字符串保存输入，避免大整数提前失真。未点击查询的输入不改变已提交条件；界面明确展示当前结果对应的订单范围，并提示未应用输入。非法输入不发送请求，原已验证结果保留。切状态或时长保留已提交订单条件，查询或清除编号回第一页；每次读取都重新验证响应订单回显和每一行，不允许混入其他订单或超过两条。

详情链接仅携带fromStatus、fromAge、fromOrderId、fromPage、fromSize这些白名单字段，不携带令牌、正文、账号或任意返回URL。详情再次验证这些字段，并只构造固定的内部列表路径；非法返回信息不读取详情，直接链接没有上下文时使用默认列表。带订单筛选的返回上下文必须与详情订单一致。

返回使用服务器实际显示页码，而不是请求但已被收缩的旧页码；返回列表再次查询，不恢复缓存业务数据。处理后原工单可从OPEN筛选消失，页数减少是正常最新结果。状态/时长/编号条件保持，不代表查询人或授权身份保持；服务器每次重新鉴权。

本课无新增软件包、表、索引、迁移、MQ资源或任务。真实数据库、图片、配置和权限保持；写入测试仅在临时测试环境。查询页使用既有复合主键按订单前缀查询，不进行大规模性能承诺。

测试覆盖规范编号及最大安全整数、SQL参数绑定、权限、双方反馈、空结果、条件交集、分页前筛选和处理后收缩、只读与并发快照；前端覆盖精确响应、返回上下文往返、无外部跳转、非法参数、实际页码和过期响应隔离。前后端应一起更新列表新增orderId回显。
