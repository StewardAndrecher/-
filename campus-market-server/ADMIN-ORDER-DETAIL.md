# 第98课：管理员订单详情与进度时间线

新增软件包0、数据库迁移0。管理员订单列表新增“查看详情与进度”，进入uni-app第28个路由pages/admin/order-detail?id=订单编号。复用已有订单和order_events，只读，不修改业务状态或补写事件。

## 接口与最小响应

GET /api/admin/orders/{id}。实时管理员授权，匿名/无效会话401，普通用户或已撤权403；成功no-store。id为1～9007199254740991的规范十进制正整数文本，拒绝前导零、负数、小数、科学计数和越界；无效400，未知订单404。

响应order包含13项快照字段：id、productId、productTitleSnapshot、priceInCentsSnapshot、status、createdAt、paymentDueAt、paidAt、deliveredAt、completedAt、cancelledAt、closedAt、paymentKind。

events只包含sequence、action、fromStatus、toStatus、actorRole、occurredAt、recordedAt。不返回买卖双方账号、ID、昵称、操作人ID/昵称、requestId或令牌。服务内部读取收件人/操作人编号仅用于核对事件角色，响应中剔除。商品当前编辑不改变下单标题和金额快照。

## 一致性与异常

只读REPEATABLE_READ事务内先读订单，再读该订单的事件，按event_no升序、LIMIT 5防御超量。现有数据库约束最多4条事件。验证连续序号、唯一动作、合法状态转移、操作角色及其内部身份、事件发生时间和订单阶段时间一致、入库时间不早于发生时间、事件/入库时间按序，以及最后状态等于订单当前状态。

事件缺失、断档、身份/时间/状态不一致返回503 ADMIN_ORDER_HISTORY_UNAVAILABLE，不返回虚假的空历史，不猜测补造事件；数据库查询失败仍为500。历史快照HISTORY_SNAPSHOT只能是首条、SYSTEM角色，不接收虚构操作人；它仅证明迁移时观察到该状态，不能还原此前的完整操作历史。历史快照后允许原状态机合法的新事件。

事务超时5秒，不等于端到端HTTP最大耗时承诺。单次详情共享快照；从列表进入详情是新请求，订单可能正常推进，应以本次详情为准。没有新增付款、关闭、交付、收货或退款按钮。

## 前端

列表点击详情，传递经过正整数校验的订单ID。返回列表恢复原筛选/页码并重新读取。查询输入错误移到输入框旁，避免长列表把提示推到屏幕外。

详情校验ID、下单快照、六状态生命周期、SIMULATED标记、事件状态链和时间，并拒绝含参与者身份/操作人身份的错误接口响应。时间按服务器本地DATETIME显示，用标准化字符串比较精度，不按设备时区转换，也不靠设备时间判断过期。

复用createAdminLoader：账号/Token变化、隐藏或卸载使旧回调失效；刷新失败清掉旧详情和时间线，不用上次成功数据伪装新结果。页面区分未登录、权限不足、未知订单、记录异常。模拟付款文案明确无真实扣款；HISTORY_SNAPSHOT显示历史边界提示。
