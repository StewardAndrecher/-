# 第78课：前端错误与后端日志关联

公共请求模块和图片上传模块都读取后端`X-Request-Id`响应头，严格校验后保存到`ApiError.requestId`。

- 500～599：在原message末尾增加`（请求编号：32位编号）`，原页面读取error.message即可显示。
- 400、401、403、409、429等：保留原提示，错误对象仍可携带编号。
- 超时、断网、客户端配置错误、未登录即在本地拒绝：没有后端响应编号，不生成假编号。
- 成功响应的数据结构不变。

复现问题后，将完整编号复制到IDEA日志搜索框，或在后端目录运行：

```sh
rg -F '替换为实际的32位编号' data/logs/campus-market.log
```

过滤器会将同一请求的异常首行和完成摘要关联起来。摘要只记路由模板、状态、方法与耗时。编号不是登录凭证、请求幂等键或订单ID。

Web端需要后端通过`Access-Control-Expose-Headers`暴露响应头；本课已处理，并保留原先的Retry-After。小程序/App使用平台提供的响应header对象，按大小写不敏感读取。本课没有增加客户端自定义请求头。

验证：`node --test tools/*.test.mjs`；三个目标平台编译使用`sh tools/build.sh all`。App编译仅代表资源可构建，不代表完成真机验收。
