# 第124课：账号资料页的会话与异步请求隔离

本课不新增软件包，不修改后端接口、表结构或权限。复用 Vue 的 watch、uni-app 生命周期和既有 createPageTaskScope。

## 原有问题

资料页原来只检查页面是否卸载、请求的 token 是否相同。页面隐藏没有清空资料和昵称草稿；同一账号换 token 没有同步重置。旧请求 finally 无条件释放 loading/saving，甚至会自动再次加载，可能干扰新会话。

## 当前行为

- onShow 开启新的页面代次，清空旧状态，读取当前账号资料。
- onHide 立即使已有任务失效，清空账号快照、未保存草稿、预期昵称、冲突/不确定提示及按钮锁。返回页面重新读取服务端。页面提示“离开此页会清除未保存的昵称草稿”。草稿不持久化。
- onUnload 永久关闭该页面作用域，后续回调不能重新启动读取。
- 同步监听账号 ID 与 token。切换账号、退出、同账号重新登录均清理旧状态；可见且已登录时重新加载。只更新同一会话昵称不重置，避免自己的保存回包触发重入。
- 加载和保存均 capture 一个只读任务票据；成功、错误、finally 都通过 valid 检查后才能更新页面或用户资料。旧任务不能释放新任务的按钮锁。
- 导航回调同样检查页面可见性、会话及忙碌状态。

## 保留的业务约束

- PUT 仍发送 nickname 与 expectedNickname，避免覆盖另一处的昵称修改。
- 可见页面内普通刷新保留草稿。发现服务端昵称变化则提示冲突；明确选择重新加载才替换草稿。
- 409 保留草稿并阻止重复保存；超时、500 及错误成功回包表示结果不确定，需要重新加载核对。不会自动重试写请求。
- 昵称按 Unicode 码点计数，1～30 字符，禁止控制字符；读写回包必须匹配发起账号。

## 边界

前端丢弃迟到回包，不等于取消已经发出的 HTTP 请求。隐藏期间已经发送的昵称修改仍可能在服务端成功；返回后 GET 资料确认当前状态。账号鉴权和昵称并发控制仍由后端完成。

## 验证

`tools/profile-lifecycle.test.mjs` 提取实际 Vue 页面脚本，通过可控 Promise 验证页面隐藏/卸载、注销、同账号换令牌、跨账号、迟到成功/失败、旧 finally、新请求锁、昵称冲突、不确定结果、Unicode、导航及重复提交。它属于页面脚本单元测试；真实浏览器和私有后端的验收结果见本课验收报告。
