# 第97课：管理员订单检索

新增软件包0、数据库迁移0。交易运营概览新增“查看订单明细”和“查看到期待付款订单”，进入uni-app第27个路由pages/admin/order-list。只定位订单快照，不提供关闭、付款、交付、收货或退款操作。

## 接口与输入

GET /api/admin/orders?status=OVERDUE_PENDING&orderId=&page=1&size=10

实时管理员权限；未登录401，普通用户或撤权账号403，响应no-store。所有筛选在SQL中完成。status默认ALL，支持六种订单状态和OVERDUE_PENDING，共8种条件。orderId为空表示不限；非空必须为1～9007199254740991的规范正整数文本，拒绝前导零、正负号、空格、小数、科学计数、越界和注入文本。编号与状态取交集，不存在编号返回空结果200。page为1～2147483647，size为1～20；超出最后页回到最后页，空集为第1/1页。

响应records、total、page、size、totalPages、status、orderId、sampledAt。每条记录只包含id、productId、productTitleSnapshot、priceInCentsSnapshot、status、createdAt、paymentDueAt。不返回买卖双方信息、requestId、令牌或商品正文。标题和金额来自下单快照，不跟随当前商品编辑变化。

## 一致性

只读REPEATABLE_READ事务中先取数据库CURRENT_TIMESTAMP(6)作为本请求到期判断基准，然后COUNT与分页行复用同一条件及基准。OVERDUE_PENDING明确为PENDING_PAYMENT且payment_due_at<=基准；请求期间跨过截止时刻也不改变本次筛选边界。基准不是客户端时间，也不宣称它等于InnoDB快照建立的精确时刻。

COUNT和行在同一事务快照，排序created_at DESC,id DESC，同创建时间仍稳定排序。总页数用整数运算，OFFSET用long计算。动态状态分支来自服务器白名单，编号与时间均绑定参数。

基准、总数和列表只在本请求内有效；概览接口及后续翻页属于独立请求，订单可能流转，不能声称跨页快照或永不重复。读取不会关闭到期订单，也不会写订单事件或通知。事务超时5秒，不等于端到端HTTP总耗时承诺。

## 前端

支持状态选择、编号精确查询、重置、上下页。查询期间禁止重复操作；成功结果明确回显真正执行的筛选条件。校验安全整数、筛选回显、页码收缩、记录数、状态、精确编号、重复ID和排序。金额按整数分格式化。

复用createAdminLoader，并复制查询条件。账号/Token变化时页面重置查询，隐藏或卸载使在途结果失效。失败清掉旧成功列表，不把权限/数据库错误伪装为空订单；非法输入直接提示，不发错误请求。翻页沿用上次成功条件，不能悄悄带入尚未提交的输入框文字。

## 验收与边界

新增25项私有MySQL集成测试、1项API文档契约测试与19项前端测试。覆盖六状态、到期边界、精确编号、组合条件、输入校验、页大小、稳定排序、页码收缩、事务快照、原快照金额、权限和只读行为。

界面样本只放私有临时库，原业务库不注入测试订单或改变订单状态。本课无索引、SQL历史、支付、MQ权限或管理员授权变更。分页为COUNT/OFFSET，适合当前教学规模；深页及大表查询可能变慢，未宣称海量高并发能力。小程序/App编译不代替手机运行，App资源不等于安装包。
