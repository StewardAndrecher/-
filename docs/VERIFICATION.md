### 最近完整回归的重跑说明

2026-10-24 完整 Java 执行生成了 1973 项报告，`NotificationIntegrationTest` 中 9 项因测试订单删除前缺少新资金关联表的夹具清理而报错。随后只给私有测试夹具补了一次清理调用，重跑该类的 35 项测试，全部通过。业务代码和断言没有因此修改；其余 108 个通过的类复用原执行记录。

所以该记录是**一次完整执行 + 一个受影响类的重跑**，不是修改后重新执行全部 1973 项的一次全绿运行。原始完整报告与专项重跑报告分开保留在本机，公开摘要如实记录此范围；后续 CI 结果单独判断。

本次上传目录已重新执行后端快速层 148 项、后端工具 77 项、前端工具 14 项及前端/桌面 1105 项，全部通过。桌面服务测试初次因运行环境限制不能绑定回环端口，取得正常本机执行权限后完整重跑通过；没有删除或跳过测试。

### 合成数据上的 SQL 对比

在本地私有 MySQL 生成 **1 万用户、10 万商品和 10 万订单**，使用 `EXPLAIN ANALYZE` 比较索引前后的热查询。以下是单次执行计划记录的服务器用时：

| 查询 | 索引前 | 索引后 | 变化 |
| --- | --- | --- | --- |
| 买家 + 状态，取 20 笔订单 | 1.59 ms | 0.0459 ms | 使用买家/状态/创建时间复合索引 |
| 卖家 + 状态，取 20 笔订单 | 1.38 ms | 0.0475 ms | 使用卖家/状态/创建时间复合索引 |
| 买家状态聚合 | 15.7 ms | 3.27 ms | 覆盖索引，减少临时聚合 |
| 标题包含关键词的计数 | 51.7 ms | 49.1 ms | 仍存在扫描成本，未被此次索引解决 |

[完整合成 SQL 测量 JSON](benchmarks/database-100k.json) 还包含 7 次热查询分位数及 8 并发、80 次只读探测。它们**不代表生产 QPS、接口端到端延迟或真实用户容量**。包含关键词、深 OFFSET 和大范围统计仍需继续观察。
